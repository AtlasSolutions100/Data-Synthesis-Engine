# Testing read-excel-file (xlsx) under vitest + jsdom

- **jsdom's `Blob` has no `arrayBuffer()`.** Any test that fetches an xlsx and
  relies on `blob.arrayBuffer()` will throw `blob.arrayBuffer is not a function`.
  The SpreadsheetPreview component treats the fetched blob as **opaque** (caches
  it, hands it straight to the parser), so in tests make `res.blob()` return the
  raw Node `Buffer` and stream it with `Readable.from(buffer)`.

- **Bridge the mocked browser lib to the real node parser.** `read-excel-file`
  is globally `vi.mock`-ed so most tests can stub rows. To exercise real
  multi-sheet parsing, `mockImplementation` the mocked `default`/`readSheetNames`
  to delegate to `read-excel-file/node` (`readXlsxFileNode`,
  `readSheetNames`) via `Readable.from(buffer)`. `afterEach` `mockReset()` keeps
  this per-test so stubbed tests are unaffected. Import the node parser from the
  `read-excel-file/node` subpath — it is NOT covered by the `read-excel-file`
  mock.

- **No xlsx writer is installed.** Real `.xlsx` fixtures are generated by
  `artifacts/books/scripts/make-xlsx-fixtures.mjs`, which builds a stored
  (uncompressed) ZIP of OOXML parts by hand with correct CRC-32s. Rerun it to
  regenerate `src/components/__fixtures__/*.xlsx`.

**Why:** the component only shows a sheet selector when a workbook has >1 sheet
and re-parses on switch; verifying that against a genuine multi-sheet workbook
requires real parsing, not stubbed row arrays.
